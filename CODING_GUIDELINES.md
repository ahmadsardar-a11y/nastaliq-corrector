## Python Best Practices

### Code Style
- Follow PEP 8 naming: `snake_case` functions/variables, `PascalCase` classes, `UPPER_CASE` constants
- Maximum line length: 88 characters (Black default)
- Use type hints for ALL function parameters and returns
- Use `Optional[Type]` instead of `Type | None` (Python 3.11 compat)
- Absolute imports only

### FastAPI Specific
- Use Pydantic models for request/response validation
- Document APIs with OpenAPI (auto-generated by FastAPI)
- Use proper HTTP status codes: 200, 400, 422, 500
- Implement consistent error responses: `{ "detail": "friendly message" }`
- Use `UploadFile` from FastAPI for image uploads

### CV Pipeline
- Each pipeline stage is a pure function: `input_ndarray → output_ndarray + metadata`
- No global state in pipeline functions
- Pass parameters explicitly (no hidden config)
- Annotate with OpenCV drawing functions, return annotated copy (don't mutate original)

## Clean Code Rules

### Constants Over Magic Numbers
- All thresholds (blur variance, brightness, min resolution) as named constants at module top
- Example: `MIN_RESOLUTION = 500`, `BLUR_THRESHOLD = 50`

### Single Responsibility
- One function per pipeline stage: `preprocess()`, `segment()`, `classify()`, `measure()`, `annotate()`
- If a function does more than one thing, split it

### DRY (Don't Repeat Yourself)
- Shared image I/O and drawing utilities in `utils.py`
- Reference loading cached with `functools.lru_cache`

### Meaningful Names
- `detect_letter_blobs()` not `find()`
- `baseline_offset_px` not `off`
- `reference_library` not `refs`

### Smart Comments
- Don't comment what code does — make it self-documenting
- Comment WHY: `# Nastaliq baseline is ~65% down from top of bounding box`

## Code Quality Rules

- File-by-file changes only — one edit per file in a single chunk
- No apologies in code or comments
- No "I understand" or "this does" filler comments
- Don't remove unrelated functionality
- Preserve existing code structures
- Don't summarize changes in commit messages (just describe what changed)
- No whitespace-only changes
- No unnecessary confirmations in code

## Testing Rules

- Write pytest tests BEFORE fixing bugs (TDD discipline)
- Use `pytest` fixtures for common test data (sample images)
- Mock external resources (file system, font loading) where appropriate
- Test error paths, not just happy paths
- Coverage target: 80% for pipeline functions, 100% for API routes

## Error Handling

- Custom exception classes for pipeline errors: `PipelineError`, `QualityGateError`
- NEVER return raw HTTP status text to users ("403 Forbidden") — always JSON with friendly message
- Graceful degradation: if one letter fails, annotate the rest
- Log exceptions server-side, return clean messages client-side

## Security

- No user input executed (no `eval`, no SQL, no shell commands)
- Uploaded images: validate format, size, content type
- No file paths from user input
- CORS configured for known origins only (or open for personal use with warning)
- No secrets in code — use environment variables

## Performance

- Downsample image for analysis if >2MP (keep display resolution for annotation)
- Use `cv2.matchTemplate` with early-exit if confidence is high enough
- Cache reference images in memory on startup, not per-request
- Process images in memory — no disk writes during request handling
